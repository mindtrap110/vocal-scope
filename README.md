# 보컬 스코프 3.7.0

기존 녹음 버튼에 2026-10-14 판단 보정 명세를 선택적으로 적용하는 정적 PWA입니다. 기본값은 훈련 꺼짐입니다. 별도 훈련 시작 버튼이나 M1 화면은 없습니다.

## 음량 기록·표시 (2026-10-19)

- 새 녹음의 세션 최상위 `levelDb`에 첫 음정 검출 후 500~2500ms 입력 RMS를 dBFS로 계산해 소수 한 자리로 저장합니다. 일반 녹음과 훈련의 initial/correction/retry/discarded에 적용합니다.
- 계산은 `10 × log10(Σx² / N)`(즉 `20 × log10(RMS)`)입니다. 음정 분석 전 입력 PCM을 사용하고, 겹치는 분석 버퍼의 같은 샘플을 중복 합산하지 않습니다. 음정이 끊긴 부분도 입력 크기 계산에 포함하며 기존 assessment 함수는 유지합니다.
- 2.5초 전에 끝나는 화면 교정 등은 500~2500ms 중 실제 수집한 부분을 사용합니다. 이 구간의 샘플이 없거나 전부 무음이면 null입니다. 마이크를 사용하지 않는 beat 교정은 null, screen 교정은 기준음이 포함된 값이며 `mixedWithReference: true` 표시를 유지합니다.
- initial·retry 녹음 중에는 음정·그래프를 숨긴 상태로 크기 막대만 표시합니다. 목표 범위 안은 초록색, 밖은 회색입니다. 막대의 띠가 목표 범위입니다.
- 훈련 설정의 **목표 크기(dB)**는 처음에는 비어 있습니다. 마이크 입력 기준의 dBFS 값(예: -30)을 직접 입력합니다. **허용 폭(±dB)**의 기본값은 4이며 두 설정은 기기에 저장합니다. 목표가 비어 있으면 범위 띠 없이 회색 막대만 표시합니다.
- 결과 공개 후와 저장 기록 상세에서 입력 크기를 확인할 수 있습니다. 요약 공유·전체 JSON·하루 JSON에 `levelDb`를 포함합니다. 이전 기록에 없는 값은 추정해 채우지 않습니다.
- 하루 JSON의 최상위 `initialLevelDbMedian`은 해당 dayId의 initial 세션 중 유한한 `levelDb` 값들의 중앙값입니다. correction/retry/discarded와 과거 미측정 기록은 이 집계에 넣지 않습니다. 유효 값이 없으면 null입니다.
- dBFS는 녹음된 입력 신호의 크기입니다. 실제 iPhone에서 '아'를 같은 크기로 3초씩 두 번 녹음하고, 결과의 `levelDb` 차이가 2dB 이내인지 확인하세요. 같은 거리·마이크·기기 설정을 유지합니다.

## 교정 방식 모드 (2026-10-19)

- 새 훈련의 기본값은 **화면만**입니다. 입력 날짜와 관계없이 블록 1·2 모두 `method: "screen"`으로 저장하며, 맥놀이 Y/N 질문은 표시하지 않습니다.
- **비교**는 입력한 연습 날짜의 '일'을 사용합니다. 홀수 날은 맥놀이 → 화면, 짝수 날은 화면 → 맥놀이입니다. 자정에 날짜나 순서를 자동 변경하지 않습니다.
- 모드는 훈련 시작 전 또는 회차 사이(다음 기준음을 듣기 전)에 변경할 수 있습니다. 변경 후 진행하는 회차에 적용하고 이미 저장된 기록은 다시 쓰지 않습니다.
- 이전 버전에서 진행하던 훈련은 기존 순서를 유지해 복원합니다. 새로운 날짜의 훈련에는 새 기본값을 사용하고, 사용자가 모드를 선택하면 그 설정을 보관합니다. 이전 날짜 기록의 method·판단·단계는 변경하지 않습니다.
- 확인: 2026-10-20과 2026-10-21 각각 화면만으로 24회를 진행하여 initial/correction/retry 72개 전부 screen으로 저장되는 것을 모의 마이크·DOM 테스트로 검증합니다.

## 음정 검출과 복구 수정

- 검출에 실패한 발성이 소음으로 학습되어 입력 문턱이 올라가면, 이후 정상 음정도 계속 버려지는 문제를 재현했습니다. 신뢰할 수 있는 음정은 소음 학습에서 제외하고, 최소 입력 수준을 넘는 정상 신호가 돌아오면 문턱을 낮춰 다시 검출합니다.
- 7반음보다 큰 갑작스러운 이동은 가까운 음정 후보가 3번 연속 확인될 때 받아들입니다. 확인되지 않은 구간은 빈 구간으로 남기며 목표음에 맞춰 보정하지 않습니다. 실제 유지한 옥타브 이동은 새 음정으로 기록합니다.
- 분석 작업이 1.5초 이상 응답하지 않거나 오류가 나면 분석 Worker만 교체합니다. 기존 마이크 입력과 음성 녹음은 유지하고, 폐기한 Worker의 늦은 응답은 무시합니다. 정상 응답 없이 3번 교체해도 계속 실패하거나 작업을 다시 만들지 못하면 측정을 종료하는 기존 저장 경로를 사용합니다.
- 도움말의 진단 정보에 Worker 재시작 수와 보류한 음정 점프 수를 포함합니다. 500~2500ms assessment 계산 함수와 기기 오디오 입력 설정은 변경하지 않았습니다.
- 3.5.5의 음정 검출·복구 동작을 유지합니다. 이번 교정 방식 테스트는 모의 마이크·Worker를 사용하며, 사용자의 실제 iPhone에서 발생했던 신호 자체를 분석한 결과는 아닙니다.

## 기본 녹음과 훈련 전환

- 훈련 꺼짐: 날짜·목표음 24개를 입력하지 않고 기존 버튼으로 바로 측정을 시작하고 직접 정지합니다. 음정과 그래프를 실시간 표시하며 판단 입력이나 3초 자동 정지는 적용하지 않습니다. 기존 목표음·가사 구절 연습·기록 공유를 이용할 수 있습니다.
- 음성 파일 저장은 이전 버전처럼 별도 스위치로 켜고 끕니다. 기존 저장 설정을 유지하며, 음정 기록은 측정 종료 시 저장합니다.
- 판단 보정 훈련 켜짐: 같은 버튼으로 아래 훈련 절차를 진행하고 음성과 training 정보를 함께 저장합니다.
- 훈련을 끄면 현재 녹음을 저장하고 일반 녹음으로 돌아갑니다. 중단한 ②·재시도는 discarded로 저장합니다. 진행 상황과 켜짐/꺼짐 설정을 보관하므로 다시 켜서 이어갈 수 있습니다.
- 훈련을 처음 켜기 전에는 이전 버전의 훈련 진행 기록이 있어도 자동으로 켜지지 않습니다. 훈련 중 목표음은 일반 녹음의 목표음 설정을 덮어쓰지 않습니다.

## 훈련을 켠 뒤 사용

1. 연습 녹음 영역에 날짜(YYYY-MM-DD), 교정 방식 모드(화면만 / 비교), 피드백 단계, 목표음 24개를 입력합니다. 목표음은 공백 또는 /로 나눠 붙여 넣습니다.
2. 기존 녹음 버튼으로 목표음을 2초 듣습니다. 자동으로 멈춘 뒤 같은 버튼으로 ② 녹음을 시작하고 3초 부릅니다.
3. ②의 음정과 그래프는 판단 전까지 숨깁니다. 방향·크기·확신도를 입력하면 결과 보기 버튼이 켜집니다. 맞음은 크기 입력을 비활성화합니다.
4. 결과는 assessment.medianCents 그대로 표시합니다. ±25¢ 안은 맞음, 그 밖은 오차 부호에 맞는 방향이 정답입니다.
5. 오차가 25¢를 넘으면 지정된 블록의 교정을 진행하고, 기준음을 끈 3초 재시도를 합니다. 재시도에는 판단을 입력하지 않습니다.
6. 하루 JSON 내보내기는 날짜에 해당하는 두 블록의 initial/correction/retry/discarded를 전부 포함하며 createdAt 순서로 정렬합니다.

## 고정된 구조

- 하루 2블록 × 12회 = 24회. 사용자가 붙여 넣은 순서를 유지하고 앱은 새 순서를 생성하지 않습니다.
- 훈련 상단에 두 블록에 실제 적용되는 교정 방식을 표시합니다. 화면만은 화면 → 화면, 비교는 입력 날짜의 홀짝에 따른 순서입니다.
- 교정 시작 버튼에 화면/맥놀이를 명시합니다. 회차를 진행하는 동안은 모드를 바꿀 수 없어 initial·교정·재시도가 같은 method를 사용합니다.
- 피드백 단계는 사용자가 직접 설정합니다. 0은 전부, 1은 짝수 회차, 2는 3·6·9… 회차입니다. 확인하지 않는 회차도 judgement와 autoScore를 저장하며 교정과 재시도는 하지 않습니다.
- initial/retry의 assessment.status가 ok가 아니거나 발성이 중단되면 discarded로 저장하고 같은 발성 단계만 다시 진행합니다.
- 기존 500~2500ms 중앙값 함수는 변경하지 않았습니다. 짧고 끊긴 구간의 처리도 그대로 유지합니다.

## 교정

- beat: 마이크와 녹음을 끄고 기준음만 재생합니다. 사용자가 끄거나 최대 6초 뒤 멈춥니다. Y/N을 필수 입력한 후 points가 빈 교정 레코드와 시작·끝 시각을 저장합니다.
- screen: 기준음을 켠 채 마이크·녹음·실시간 음정 표시를 사용합니다. 사용자가 2초 맞춘 뒤 정지하면 기준음도 멈춥니다. points와 mixedWithReference=true를 보존하며 이 세션을 재시도 결과로 표시하거나 평가하지 않습니다.
- 기준음은 12개 배음의 진폭을 각각 1/n으로 합성하고 시작·끝에 20ms 페이드를 적용합니다. C4=60, A4=440Hz입니다.
- 기존 getUserMedia 옵션과 출력 AudioContext 구성을 유지했습니다. 실제 iPhone의 에어팟 출력·내장 마이크 입력은 기기에서 확인해야 합니다.

## 저장과 내보내기

훈련을 켜고 녹음한 각 레코드의 training에는 dayId, block, method, trial, stage, targetNote, targetMidi, judgement, autoScore, beatHeard, mixedWithReference, initialSessionId, feedbackLevel을 저장합니다. 일반 녹음의 training은 null입니다.

- 새 세션의 최상위 levelDb는 0.5~2.5초 입력 크기(dBFS)이며, 음성 파일과 별도로 JSON에 저장합니다.
- judgement/autoScore는 initial에서만, beatHeard는 beat correction에서만 채웁니다.
- correction/retry의 initialSessionId는 같은 회차의 initial 레코드 ID입니다.
- 판단이 없는 기록도 제외하지 않습니다.
- 파일명은 vocal-scope-training-YYYY-MM-DD.json입니다.
- 음성 파일은 IndexedDB에 별도로 저장하고, 기존 녹음 목록에서 재생·공유·파일 저장할 수 있습니다.
- 이전에 training=null로 저장된 레코드의 판단·회차는 새로 추정해서 채우지 않습니다.

## 검증

- `npm install --no-save --ignore-scripts jsdom@26.1.0` 후 `node tests/correction-mode-test.cjs`를 실행합니다.
- 화면만 기본값, 10/20·10/21 각각 24회와 두 블록의 실제 저장·하루 내보내기 데이터, 화면 교정 points·mixedWithReference, Y/N 미표시, 비교 홀짝, 모드 변경·복원, 이전 기록 보존, 일반 녹음, assessment 함수 해시 동일성을 검사합니다.
- `node tests/service-worker-test.cjs`는 모든 버전별 자산의 존재와 오프라인 캐시·업데이트 동작을 검사합니다.
- `node tests/level-test.cjs`는 44.1/48kHz 파형의 RMS·시간 구간·버퍼 중복 제거, 실제 음정 검출기를 거친 동일한 3초 합성 모음의 두 번 기록(2dB 이내), 크기 막대 색과 음정 숨김, 설정 복원, 짧은 화면 교정, 음정 실패 시 음량, 실제 하루 JSON 파일 생성·중앙값 집계를 검사합니다. 실제 사용자의 발성 반복성이나 iPhone 마이크를 대신 검증한 결과는 아닙니다.
- GitHub Actions에서 JS 문법 검사, 위 테스트와 합성음 음정 검출 smoke test를 실행합니다. 실제 iPhone의 오디오 출력·입력과 음성 파일 저장은 기기에서 확인해야 합니다.

정적 파일을 GitHub Pages 같은 HTTPS 호스팅에 배포합니다. 녹음과 기록은 이 기기의 브라우저 저장소에 보관되므로 중요한 파일은 별도로 내보내세요.
